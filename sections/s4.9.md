Una regla es recursiva cuando su conclusión puede alimentar, directa o
indirectamente, su propio antecedente. La recursión es la forma normal de
definir relaciones transitivas en la programación lógica. En Residuum la
recursión es legal en el lenguaje, pero no en todos sus evaluadores. Esta
sección dice dónde se admite y dónde se rechaza. Las demostraciones de
terminación pertenecen a @sec:s6.11.

## Reglas recursivas

<!-- covers: 1 -->

La elaboración no prohíbe la recursión. Una regla puede concluir un verbo que
aparece en su propio antecedente. La fixture `peano_after.res` define la
suma unaria con reglas así:

```text
rule leftSuccessor(left, right, request, cursor, next, t) =
    leftWalk(left, right, request, cursor) @ t
    & successor(left, cursor, next) @ zeroTime
    <= leftWalk(left, right, request, next) @ after t
```

`leftWalk` aparece a ambos lados. Cada paso avanza el tiempo con `after`, así
que cada conclusión es un evento nuevo (@sec:s4.4). Cada operando entra como
una espina finita de `successor`, un verbo `seeded`. Con esas entradas, los
recorridos terminan. El documento del experimento lo presenta como argumento
para esa representación, no como teorema general de terminación.

El cierre acepta estas reglas. Las funciones `close` y `close_program` no
comprueban ciclos. Las pruebas de Peano las llaman desde tests de Rust,
dentro del proceso acotado de `test_safe.py`. Los documentos aclaran que eso
no es una alternativa de ejecución sin límites
(`docs/peano-polynomial-product-experiment.md`).

## La comprobación de aciclicidad

<!-- covers: 2 -->

El runner de experimentos sí comprueba ciclos. La función `require_acyclic`
(`src/experiments.rs`) construye un grafo entre verbos. Cada regla añade una
arista desde cada verbo de su antecedente hasta el verbo de su conclusión.
Los modos que activan Programs usan `require_program_acyclic`: allí un verbo
asociado añade aristas hacia las conclusiones de sus reglas. Si el grafo tiene un ciclo, el runner rechaza el módulo.

```res {#lst:s4-9-ciclo caption="Un módulo cíclico rechazado por el runner residual" run=expect-error cmd=query}
module Alcance

entity Node
const n1 : Node
const n2 : Node
const n3 : Node
const tau : PropositionTime

seeded verb edge(from : Node, to : Node)
derived verb reach(from : Node, to : Node)

rule base(a, b, t) = edge(a, b) @ t <= reach(a, b) @ t
rule step(a, b, c, t) = reach(a, b) @ t & edge(b, c) @ t <= reach(a, c) @ t

experiment path {
    seeds { edge(n1, n2) @ tau, edge(n2, n3) @ tau, }
    query residual reach(n1, n3) @ tau
}
```
::: explanation
El módulo define la alcanzabilidad en un grafo, el ejemplo clásico de
recursión en Datalog. La regla `step` concluye `reach` a partir de `reach`, y
el grafo de verbos tiene un ciclo. La elaboración acepta el módulo, pero el
runner lo rechaza antes de buscar o de cerrar. El mensaje no lleva la ruta
del fichero: es un rechazo de ejecución, no de tipos (@sec:s4.6).
:::

La comprobación es conservadora. Mira verbos, no instancias. No sabe que
una espina finita detiene un recorrido como el de Peano. Tampoco sabe que el
cierre de @lst:s4-9-ciclo es finito: con tres nodos y un solo instante, hay a
lo sumo nueve eventos `reach`. Aun así el módulo se rechaza.

El código la describe como una «condición suficiente de terminación» para el
runner. Los documentos lo dicen del modo residual: exige dependencias
acíclicas entre verbos, condición suficiente para estas fixtures
(`docs/executable-fixtures.md`). En el commit fijado, la misma comprobación
protege también `run`, `explain` y `execute` en módulos sin defaults.
`./residuum run` rechaza por eso `peano_after.res`. Los documentos de Peano lo registran: el adaptador
del CLI todavía rechaza los grafos recursivos, con un criterio conservador.

## Ciclos permitidos en el cierre y en FOUR

<!-- covers: 3 -->

Tres partes del sistema aceptan reglas cíclicas sin rechazarlas de antemano.
Cada una tiene su propia salvaguarda:

- **El cierre.** `close` y `close_program`, llamados desde Rust, aceptan reglas
  recursivas. La terminación queda a cargo del modelo y del entorno acotado.
- **La consulta FOUR.** Una consulta `fourFusion` trabaja con reglas ground.
  Por eso admite ciclos dentro de su universo finito de átomos, y el runner no
  le aplica `require_acyclic` (@sec:s6.10).
- **La búsqueda residual desde Rust.** La búsqueda detecta un ciclo de
  objetivos lógicamente iguales y falla con un error. Un ciclo que genera
  tiempos distintos lo detiene `max_depth` (@sec:s6.8).

El caso FOUR se ve con dos reglas sin parámetros, `P() @ tau <= Q() @ tau` y
`Q() @ tau <= P() @ tau`. Una consulta `query residual` sobre ese módulo se
rechaza por el ciclo. Una consulta `fourFusion` sobre el mismo módulo
responde, porque el universo tiene sólo dos átomos.

El resultado es un lenguaje con recursión y un CLI sin ella. Quien necesita
recursión desde el CLI debe reescribir la relación sin ciclos entre verbos, o
usar `fourFusion` con reglas ground. Los documentos de Residuum no anuncian un
cambio de esta política.
