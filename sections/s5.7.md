En Haskell toda función de varios argumentos está currificada. Aplicarla a un
argumento da otra función que espera el resto. Residuum ofrece lo mismo para
reglas y Programs. Una aplicación fija los primeros parámetros y deja los
demás pendientes. El resultado es otra regla, u otro Program, que puede
aplicarse después. Esta sección muestra la aplicación parcial de reglas, la de
Programs y la especialización por etapas.

## Aplicación parcial de reglas

La referencia del lenguaje da este ejemplo:

```text
rule remember(effective, t, subject) =
    observed(subject, effective) @ t <= recorded(subject, effective) @ after t
rule rememberOld = remember(oldDate)
rule rememberOldForAna = rememberOld(tau, ana)
```

Los argumentos fijan los parámetros por orden. `remember(oldDate)` fija
`effective` y deja `t` y `subject`. `rememberOld(tau, ana)` fija esos dos y da
una regla sin parámetros. El elaborador aplica tres condiciones:

- cada argumento debe ser una constante declarada;
- su tipo debe ser igual al del parámetro, sin subtipos;
- no puede haber más argumentos que parámetros.

El resultado conserva los parámetros que no recibieron valor, en su orden.
La sustitución llega a las posiciones de argumento y a los índices temporales
en una sola pasada (@sec:s5.2). Un mismo parámetro temporal puede ocupar las
dos posiciones a la vez, como `effective` en una regla con `@ effective`.

La especificación fija la obligación como parte del **THEOREM** T1: la
aplicación parcial debe coincidir con su expansión en línea, hasta
equivalencias explícitamente justificadas.

```res {#lst:s5-7-etapas caption="Una regla aplicada en dos etapas y de forma directa" run=explain}
module Etapas

entity Person

const juan : Person
const oldDate : PropositionTime
const tau : PropositionTime

seeded verb observed(subject : Person, effective : PropositionTime)
derived verb recorded(subject : Person, effective : PropositionTime)

rule remember(effective, t, subject) =
    observed(subject, effective) @ t <= recorded(subject, effective) @ after t

// Dos etapas.
rule partiallyRemember = remember(oldDate)
rule fixedRemember = partiallyRemember(tau, juan)

// Aplicación directa y expansión en línea.
rule directRemember = remember(oldDate, tau, juan)
rule inlineRemember() =
    observed(juan, oldDate) @ tau <= recorded(juan, oldDate) @ after tau

experiment right {
    seeds { observed(juan, oldDate) @ tau, }
    query residual recorded(juan, oldDate) @ after tau
}
```
::: explanation
El módulo adapta la fixture `examples/experiments/temporal_beta_arguments.res`.
Las cinco reglas concluyen el mismo evento desde el mismo seed, así que
`explain` muestra cinco justificaciones. `fixedRemember`, `directRemember` e
`inlineRemember` tienen la sustitución vacía: ya no les quedan parámetros.
`partiallyRemember` liga sólo los dos parámetros pendientes.
:::

En @lst:s5-7-etapas la regla aplicada en dos etapas y la aplicada de una vez
dejan el mismo registro, salvo el nombre de la regla. Las dos coinciden con la
versión escrita a mano. La regla general `remember` también participa: liga
sus tres parámetros con los valores del seed.

La fixture original comprueba también lo que la especialización excluye. Con
el seed `observed(juan, newDate) @ tau`, la regla fijada en `oldDate` no
concluye. Con el seed en otro instante, `sigma`, tampoco. Un valor aplicado
deja de ser un parámetro: ya no se liga con lo que traiga la evidencia.

## Aplicación parcial de Programs

<!-- covers: 2 -->

Un Program se aplica igual que una regla. La referencia del lenguaje lo
muestra con `program ForAna = Both(ana)`, que fija el parámetro `a` de `Both`.
La aplicación usa el mismo prefijo posicional de constantes tipadas, con
igualdad exacta de tipos. Sustituye el valor en todos los bindings de los
RuleUses, también dentro de records.

Tres cosas no cambian con la aplicación:

- los parámetros no aplicados siguen siendo parámetros del Program;
- las constantes capturadas siguen siendo constantes;
- los parámetros locales de cada RuleUse siguen siendo locales.

El Program aplicado conserva el ámbito léxico de su definición, aunque se
declare en otro módulo. Ninguna aplicación enlaza parámetros por coincidencia
de nombre. Aplicar un Program tampoco ejecuta nada; sólo produce otra
declaración (@sec:s5.6).

## Especialización por etapas

<!-- covers: 3 -->

La aplicación parcial permite especializar un contexto en varios pasos. La
nota `docs/legal-ontology-explicit-query-substitutions.md` lo hace con un
Program jurídico de cinco parámetros:

```text
program CompliancePartial = ComplianceContext(gConduct)
program ComplianceBound = CompliancePartial(private, gDate)
program ComplianceGround = ComplianceBound(gObject, gTau)
```

La primera etapa fija la conducta. La segunda fija la autoridad y la vigencia
del acto. La tercera fija el objeto y el tiempo. La nota verifica que la
aplicación directa de los cinco argumentos y la aplicación por etapas dejan
los mismos RuleUses y el mismo módulo léxico. Las identidades nominales de los
Programs especializados pueden diferir.

Un tiempo ya aplicado no vuelve a ser variable. `ComplianceBound` todavía
puede instanciar su tiempo pendiente con otro instante. `ComplianceGround`,
fijado en `gTau`, no da explicación para un objetivo en otro instante. Un
argumento de autoridad en una posición de conducta se rechaza.

La nota clasifica como **IMPLEMENTED + TESTED** los bindings tipados, la β por
etapas, el ámbito local y compartido y la sustitución temporal. Sus 16
consultas contextuales son un **MODEL RESULT**. En esa etapa la nota marcaba
como **NOT IMPLEMENTED** dos cosas:

- una API pública de consulta con sustituciones o con un Program como ámbito;
- la búsqueda de variables existenciales.

La nota muestra el caso con parámetros pendientes. Tras fijar sólo la
conducta, la regla `rightCompliance` conserva dos parámetros que el objetivo
no determina: la autoridad y la vigencia del acto. El requisito local los
representa con su tipo y su ámbito, pero la búsqueda sobre el Program parcial
devuelve un error. Los valores aplicados son restricciones de la consulta, no
evidencia de un acto ni valores que el motor descubra.

La primera carencia se cubrió después: la referencia del lenguaje tiene hoy
`using program` y `with` (@sec:s5.8). La segunda sigue ausente. Si después de especializar
quedan parámetros que el objetivo no determina, la búsqueda no los resuelve ni
enumera un dominio.

Conviene distinguir dos currificaciones. La de esta sección actúa sobre los
parámetros de una regla. La cláusula residual `A <= B -o C` currifica las
premisas del cuerpo: dado `A`, falta `B` (@sec:s6.8).
