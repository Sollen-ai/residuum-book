La expresividad mide cuánto puede decir un lenguaje sin rodeos. Una
idea tiene forma directa cuando una construcción del lenguaje la escribe tal
cual. Si hace falta combinar otras construcciones para simularla, la idea
necesita una codificación.

El criterio no cuenta construcciones. Pregunta qué distancia queda entre el
razonamiento del autor y el texto del programa. Una codificación puede ser
correcta y, aun así, ocultar la idea al lector. También puede costar más
tiempo de ejecución o depender de una disciplina que el compilador no
comprueba.

## El criterio en Residuum

Residuum es un lenguaje de reglas tipadas sobre eventos con tiempo. Ocho ideas
tienen en él forma directa:

<!-- covers: 1, 2, 3, 4, 5, 6, 7, 8 -->

- **Eventos tipados con tiempo.** Un evento aplica un verbo declarado a
  argumentos tipados y lo sitúa en un instante: `requests(ana, book) @ tau`.
  El tiempo es un tipo, `PropositionTime`, y `after` construye el instante
  siguiente (@sec:s4.4).
- **Conjunción.** El operador `&` une las condiciones de una regla de Horn.
- **Unidad.** `I` es la condición vacía. Una regla `I <= C` concluye `C` sin
  requisitos.
- **Negación evidencial.** `~P` es evidencia de que `P` es falso. No es la
  ausencia de una prueba de `P`.
- **Cláusulas residuales.** `A <= B -o C` dice que, dado `A`, todavía falta
  `B` para concluir `C` (@sec:s6.8).
- **Programs.** Un Program agrupa reglas con parámetros compartidos. Puede
  asociarse a un verbo y activarse cuando ocurre el evento (@sec:s5.6).
- **Defaults.** `supernormal`, `blocked when` y `exception … to … when`
  escriben una regla que vale salvo excepción (@sec:s6.9). `run` y `explain`
  los evalúan; las consultas residuales y FOUR rechazan los módulos que los
  contienen. Se pueden escribir, pero no todas las preguntas los admiten.
- **Efectos.** Un `effect verb` declara cómo cambia el estado. Derivar un
  efecto no lo ejecuta; lo ejecuta la orden `execute` (@sec:s7.4).

Estas formas no son abreviaturas de otras. Cada una tiene su propio caso en
el TypedAST y su propia lectura. Tres de ellas merecen una nota:

- El tiempo forma parte de la identidad del evento. `lent(ana, book) @ tau` y
  `lent(ana, book) @ after(tau)` son eventos distintos. Tras `@` va un nombre
  o `after` y un nombre, sin anidar; los instantes anidados aparecen como
  valores de argumentos o por inferencia.
- Un evento y su negación evidencial pueden coexistir en Known. Ninguno anula
  al otro.
- Un efecto separa dos preguntas. Si el efecto se sigue, es un evento más del
  cierre. Si el estado cambia, lo decide otra operación.

Una regla `A <= C` se lee «`A` implica `C`». La condición va a la izquierda y
la conclusión a la derecha. @Lst:s2-1-prestamo reúne cuatro de estas formas
en un solo módulo.

```res {#lst:s2-1-prestamo caption="Conjunción, negación evidencial, cláusula residual y unidad" run=run}
module Prestamo

entity Person
entity Thing

const ana : Person
const book : Thing
const tau : PropositionTime

seeded verb requests(subject : Person, object : Thing)
seeded verb available(object : Thing)
derived verb lent(subject : Person, object : Thing)
derived verb refused(subject : Person, object : Thing)
derived verb eligible(subject : Person, object : Thing)
derived verb visible(object : Thing)

// Conjunción: pedir y estar disponible implican el préstamo.
rule lending(person, object, t) =
    requests(person, object) @ t & available(object) @ t <= lent(person, object) @ t

// Negación evidencial: hace falta evidencia de que la cosa no está disponible.
rule refusal(person, object, t) =
    requests(person, object) @ t & ~available(object) @ t <= refused(person, object) @ t

// Cláusula residual: dado el pedido, falta la disponibilidad.
rule eligibility(person, object, t) =
    requests(person, object) @ t
    <= available(object) @ t
    -o eligible(person, object) @ after t

// Unidad: la conclusión vale sin condiciones.
rule catalogue() = I <= visible(book) @ tau

experiment withBook {
    seeds { requests(ana, book) @ tau, available(book) @ tau, }
    query residual lent(ana, book) @ tau
}

experiment withoutBook {
    seeds { requests(ana, book) @ tau, ~available(book) @ tau, }
    query residual refused(ana, book) @ tau
}

experiment noEvidence {
    seeds { requests(ana, book) @ tau, }
    query residual refused(ana, book) @ tau
}
```
::: explanation
El módulo declara tipos y verbos, y escribe cuatro reglas, una por forma. En
`withBook` el cierre deriva el préstamo y la elegibilidad en `after(tau)`. En
`withoutBook` la evidencia `~available` produce el rechazo. En `noEvidence`
falta esa evidencia y el rechazo no se deriva. La regla `catalogue` concluye
`visible(book)` en los tres experimentos, porque su condición es `I`.
:::

@Lst:s2-1-prolog escribe las mismas reglas en Prolog. El tiempo pasa a ser un
argumento más y `after(T)` es un término cualquiera. La negación usa `\+`, la
negación por fallo: `\+ G` tiene éxito cuando la prueba de `G` fracasa
[@clark1978negation].

```prolog {#lst:s2-1-prolog caption="Las mismas reglas en Prolog" run=none}
:- dynamic available/2.

lent(P, O, T)            :- requests(P, O, T), available(O, T).
refused(P, O, T)         :- requests(P, O, T), \+ available(O, T).
eligible(P, O, after(T)) :- requests(P, O, T), available(O, T).
visible(book, tau).

requests(ana, book, tau).

% ?- refused(ana, book, tau).
% Tiene éxito: no hay ninguna cláusula de available/2.
```
::: explanation
La declaración `dynamic` permite consultar `available/2` aunque no tenga
cláusulas. Con sólo el pedido, `refused(ana, book, tau)` tiene éxito, porque
la prueba de `available(book, tau)` fracasa. Es el caso `noEvidence` de
@lst:s2-1-prestamo, con la respuesta contraria. La regla residual queda como
una cláusula de Horn más: Prolog no distingue la premisa que falta. Nada
impide escribir `after(ana)`, porque los términos no tienen tipo.
:::

La comparación muestra dos diferencias de expresividad. Prolog dice
directamente «no se pudo probar», y Residuum no lo dice. Residuum dice
directamente «hay evidencia en contra», y Prolog necesita otro predicado para
decirlo. Residuum, además, rechaza un tiempo mal tipado antes de ejecutar.

## Lo que no tiene forma directa

<!-- covers: 9 -->

Tres ideas comunes en otros lenguajes no tienen construcción en Residuum:

- **Disyunción.** El cuerpo de una regla sólo combina eventos con `&` y `I`.
  Una alternativa se escribe con dos reglas que concluyen lo mismo. La
  disyunción aparece sólo en las respuestas de la consulta residual, no en el
  texto fuente (@sec:s6.8).
- **Cuantificadores.** Los parámetros de una regla son su única
  cuantificación. Una regla es una cláusula parametrizada, no una fórmula con
  `∀` o `∃` anidados.
- **Aritmética.** No hay números ni operaciones numéricas. La suma de Peano
  se codifica con `after` como sucesor.

El experimento de Peano muestra hasta dónde llega esa codificación. Cada
operando entra como una cadena finita de hechos de sucesor. Programs
asociados recorren las dos cadenas y el resultado de `2 + 3` aparece como
el instante `after(after(after(after(after(zeroTime)))))`. El documento lo
clasifica como **EXPERIMENTAL OBSERVATION**: el núcleo suma en unario sin
primitivas enteras. Los casos finitos no prueban completitud ni
computabilidad general.

La codificación tiene un precio claro. El resultado es un tiempo pegado a un
evento, no un valor numérico. Un experimento posterior transporta esos
tiempos como argumentos con el constructor `after`. Aun así, faltan los
enteros con signo, la resta y las comparaciones. @Sec:s2.9 evalúa qué
programas no jurídicos caben en el lenguaje.

Falta también la negación por ausencia. La auditoría del núcleo monotónico
marca `!` como **NOT IMPLEMENTED**. Lo que Prolog escribe con `\+` no tiene
equivalente en Residuum.

## Veredicto

Residuum escribe sin codificación lo que su dominio necesita:

- eventos con tiempo y condiciones;
- evidencia en contra;
- requisitos pendientes;
- excepciones y efectos.

Fuera de ese dominio, la disyunción, los cuantificadores y la aritmética
exigen codificaciones o no caben. La negación por fallo de Prolog no tiene
equivalente.

Según este criterio, Residuum ofrece un desempeño medio: expresa sin codificación el razonamiento con reglas sobre eventos, pero no tiene disyunción en las reglas, cuantificadores generales ni aritmética.
