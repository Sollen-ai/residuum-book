Un lenguaje tiene tipado estático cuando comprueba los tipos antes de
ejecutar. Es fuerte cuando ninguna operación puede aplicarse a un valor del
tipo equivocado sin que el lenguaje lo detecte [@pierce2002types]. Residuum
cumple las dos condiciones para los tipos que declara. Sin embargo, algunas
condiciones de buena formación sólo se conocen al buscar o al cerrar. Esta
sección separa los dos grupos.

## Lo que comprueba la elaboración

<!-- covers: 1 -->

La elaboración (@sec:s4.1) rechaza un módulo entero si encuentra cualquiera
de estos errores:

- **Nombres.** Un verbo, una regla, una constante o una entidad sin
  declarar.
- **Aridad.** Un evento con más o menos argumentos que su verbo.
- **Tipos de argumento.** Un valor no asignable a la posición del verbo, en
  un seed, en una premisa, en un objetivo o dentro de una regla.
- **Tiempos.** Un tiempo que no es `PropositionTime`, o un tiempo ground que
  no es una constante declarada.
- **Records.** Un campo que falta, que sobra o que se repite, o un valor de
  campo de otro tipo.
- **Clases de verbo.** Un seed de un verbo que no es `seeded`, o una regla que
  concluye la negación evidencial de un verbo `seeded`.
- **Efectos.** Un `+=` sobre un campo que no es conjunto, o un valor de otro
  tipo de elemento.
- **Programs.** Un binding de RuleUse de tipo incompatible, un parámetro
  desconocido o repetido, o una asociación con firma distinta de la del verbo.
- **Consultas.** Un `with` sin `using`, el modo `active` con `fourFusion`, o
  un binding de consulta mal formado.

El último punto incluye los bindings de consulta. La elaboración los valida
al leer el experimento, sin buscar ni cerrar nada. Comprueba que el parámetro
exista, que su ámbito esté entre las reglas elegidas y que el valor tenga el
tipo correcto. También comprueba que no contradiga la cabecera de una regla
que concluye el objetivo. @Lst:s4-6-binding muestra el error de tipo.

```res {#lst:s4-6-binding caption="Un binding de consulta del tipo incorrecto" run=expect-error cmd=query}
module Prestamo

entity Person
entity Thing

const ana : Person
const book : Thing
const tau : PropositionTime

seeded verb requests(subject : Person, object : Thing)
derived verb lent(subject : Person, object : Thing)

rule lending(person, object, t) = requests(person, object) @ t <= lent(person, object) @ t

experiment wrongType {
    seeds { requests(ana, book) @ tau, }
    query residual lent(ana, book) @ tau
    using rules { lending }
    with { rule lending.person = book }
}
```
::: explanation
El parámetro `person` de `lending` tiene tipo `Person`, inferido del verbo
`requests`. El binding le asigna `book`, una `Thing`. La elaboración rechaza
el módulo antes de buscar. El mensaje lleva delante el nombre del fichero,
como todo error que sale del resolver de módulos.
:::

## Lo que queda para la ejecución

<!-- covers: 2 -->

Algunos rechazos dependen del objetivo, de la evidencia o de la forma del
grafo de reglas. La elaboración no los ve, y el runner o la búsqueda los
detectan después:

- **Ciclos.** El runner rechaza un módulo con dependencias cíclicas entre
  verbos antes de cerrar o buscar (@sec:s4.9).
- **Programs y defaults.** Una consulta sobre un módulo con Programs exige
  ámbito explícito o modo activo; una consulta sobre un módulo con defaults se
  rechaza (@sec:s6.9).
- **Parámetros sin determinar.** Si la cabecera de una regla y los bindings no
  fijan un parámetro del cuerpo, la búsqueda falla. El mensaje dice «not
  determined by the goal» (@sec:s4.7).
- **Conflictos durante la búsqueda.** Un binding compatible con el objetivo
  puede chocar con un subobjetivo. La búsqueda da entonces un error, no una
  regla ausente en silencio.
- **Límites.** La búsqueda puede agotar `SearchLimits` (@sec:s6.8), y el
  proceso puede agotar los límites del runner (@sec:s7.2).

Estos errores no son errores de tipo en sentido estricto. Ninguno permite
aplicar una operación a un valor mal tipado. Todos detienen la evaluación con
un error explícito, y ninguno entrega un resultado parcial como si fuera
completo.

La forma del mensaje ayuda a distinguirlos. Un error de elaboración lleva
delante la ruta del fichero, porque lo produce el resolver de módulos. Un
error de ejecución no la lleva.

Queda un hueco que el código declara. La API de Rust admite un `Term::Var`
como identidad opaca de runtime. Su tipo lo afirma quien llama, y Residuum no
lo comprueba contra ninguna declaración. Los documentos lo dicen así: las
variables opacas siguen dependiendo del tipo suministrado. Ese hueco no
existe en el código fuente `.res`, donde todo valor de un binding es una
constante, `none`, un record o un constructor. @Sec:s5.8 vuelve sobre la
seguridad de tipos de los bindings.
