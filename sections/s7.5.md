Un programa Residuum puede fallar antes de responder. El fichero puede estar
mal escrito, una consulta puede salir del fragmento admitido o un efecto puede
chocar con otro. En todos esos casos Residuum se detiene con un mensaje. No
entrega una respuesta parcial como si fuera completa. Esta sección clasifica
esos fallos por etapa y muestra tres de ellos.

## Categorías de error por etapa

<!-- covers: 1 -->

Cada etapa del pipeline tiene sus propios errores (@sec:s1.4). En el código,
la elaboración (`src/elab.rs`) y el runtime (`src/runtime.rs`) usan un tipo
`Error` que sólo guarda un mensaje. No hay códigos numéricos ni jerarquía de
clases. La etapa se reconoce por el momento en que aparece el error y por el
texto del mensaje.

El error llega al usuario por stderr, con dos formatos. El worker escribe
`residuum:` seguido del mensaje y termina con un código de fallo
(`src/bin/residuum.rs`). Si el fallo es de la elaboración, el mensaje empieza
por el nombre del fichero. El launcher, en cambio, rechaza una orden mal
escrita con su texto de uso y el código 2, antes de compilar nada. Cuando el
runner detiene una etapa, añade una línea `STOPPED` con el motivo
(@sec:s7.2).

| Etapa | Ejemplos de rechazo |
|---|---|
| Launcher y runner | Orden desconocida; `--steps` fuera de 1..4096; fichero raíz de más de 64 KiB; límites que no se pueden imponer (@sec:s7.2) |
| Carga del fichero | Import inexistente, absoluto o cíclico; más de 1 MiB o 64 módulos en el grafo de imports |
| Análisis sintáctico | Un comentario de bloque sin cerrar |
| Elaboración | Verbo, constante o campo desconocido; aridad o tipo incorrecto; `seeds` con un verbo que no es `seeded`; símbolo duplicado |
| Consulta | Parámetro que el objetivo no determina; ciclo de objetivos; límite de búsqueda agotado; consulta residual con defaults |
| Ejecución | Campo ausente; campo que no es conjunto; instante sin resolver; conflicto entre efectos |

: Errores por etapa {#tbl:s7-5-etapas}

La elaboración comprueba todo lo que puede antes de ejecutar nada. Los
argumentos de los seeds deben ser términos ground de tipos compatibles. Un
tiempo sin declarar, un argumento desconocido, una aridad incorrecta o un tipo
incompatible fallan en esa etapa (`docs/executable-fixtures.md`).

```res {#lst:s7-5-aridad caption="Un evento con aridad incorrecta" run=expect-error setup=s7-5-base}
experiment wrongArity {
    seeds { sells(juan, car) @ tau, }
    query residual owns(pedro, car) @ after tau
}
```
::: explanation
El setup oculto declara `sells` con tres argumentos y `owns` con dos. El seed
sólo da dos argumentos a `sells`. La elaboración rechaza el módulo antes de
calcular ningún cierre. El mensaje nombra el fichero, el verbo y las dos
aridades.
:::

En @lst:s7-5-aridad el error aparece aunque la orden sea `run`. Ningún
experimento llega a evaluarse. Un módulo mal tipado no tiene cierre.

## Rechazos en lugar de respuestas parciales

<!-- covers: 2 -->

La consulta residual tiene un fragmento admitido estrecho (@sec:s6.8). Cada
parámetro de una regla útil debe quedar fijado por la cabeza o por un binding
explícito. Residuum no enumera las constantes del módulo para probar valores.
Cuando un parámetro queda libre, la consulta falla.

```res {#lst:s7-5-parametro caption="Un parámetro que la cabeza no fija" run=expect-error cmd=query setup=s7-5-base}
rule resale(seller, middle, object, buyer, t) =
    sells(seller, object, middle) @ t & sells(middle, object, buyer) @ t
    <= owns(buyer, object) @ after t

experiment chain {
    seeds { sells(juan, car, pedro) @ tau, }
    query residual owns(pedro, car) @ after tau
}
```
::: explanation
La regla `resale` concluye `owns(buyer, object)`. Su cabeza fija `buyer`,
`object` y `t`, pero no `seller` ni `middle`. La consulta residual no busca
valores para esos parámetros entre las constantes. Rechaza la consulta y
nombra la regla y el parámetro.
:::

El rechazo de @lst:s7-5-parametro es deliberado. Una búsqueda que ignorara la
regla devolvería «no hay explicación», y eso sería falso. Una búsqueda que
probara constantes saldría del contrato. Residuum prefiere decir que no puede
responder. El error aparece en la etapa de consulta, no en la elaboración: el
módulo está bien tipado. A diferencia de los otros dos listados, el mensaje no
empieza por el nombre del fichero.

La misma política vale en otros puntos:

- **Límites de búsqueda.** Si la búsqueda agota `SearchLimits`, devuelve un
  error y descarta toda la evaluación. Nunca entrega un prefijo de
  resultados (@sec:s6.8).
- **Evaluación por pasos.** Una traza acotada distingue siempre el cierre
  completo de un prefijo incompleto (@sec:s6.6). Los errores son terminales y
  nunca producen un éxito truncado (`docs/stepwise-evaluation.md`).
- **Ejecución.** Un conflicto entre efectos detiene la ejecución sin aplicar
  los efectos en conflicto (@sec:s7.4).
- **Recursos.** El runner detiene el proceso al acercarse al límite de
  memoria o al vencer el timeout. No hay salida parcial que pase por buena
  (@sec:s7.2).

## Mensajes de error que indican la corrección

<!-- covers: 3 -->

Muchos mensajes dicen qué cambiar, no sólo qué falló. Las consultas FOUR con
ámbito son el caso más claro. Todo parámetro que aparece en el cuerpo de una
regla del ámbito necesita un binding. Si falta, el error nombra el destino
`with` que lo fijaría (`docs/executable-fixtures.md`).

```res {#lst:s7-5-binding caption="Un binding que falta en una consulta FOUR" run=expect-error cmd=query setup=s7-5-base}
derived verb notified(person : Person)
derived verb served(person : Person)

rule service(person, t) = notified(person) @ t <= served(person) @ t

experiment contraposition {
    premises { ~served(juan) @ tau, }
    query fourFusion ~notified(juan) @ tau
    using rules { service }
    with { rule service.person = juan }
}
```
::: explanation
La regla `service` se lee «`notified` implica `served`». La consulta FOUR pide
la contraposición para `juan`. El bloque `with` fija `person`, pero no `t`. El
mensaje nombra el destino exacto que falta, `rule service.t`. Basta añadir
`rule service.t = tau` al bloque `with`.
:::

El mensaje de @lst:s7-5-binding usa la misma sintaxis que el programa. El
lector puede copiar el destino al bloque `with`. Otros mensajes del código
siguen la misma pauta:

- el binario interno que no encuentra sus límites dice «use the repository's
  residuum launcher» (`src/bin/residuum.rs`);
- un binding temporal sin resolver indica que se omita el binding para dejar
  el parámetro pendiente (`src/residual/bindings.rs`);
- un binding explícito sin ámbito dice que exige un ámbito de búsqueda
  explícito (`src/residual/bindings.rs`).

No todos los mensajes llegan tan lejos. «verb `sells` expects 3 args, got 2»
dice qué está mal, pero no muestra la declaración. Los mensajes de
@lst:s7-5-aridad y @lst:s7-5-binding nombran el fichero, pero no la línea.
Los mensajes del código están en inglés, aunque los documentos del proyecto
estén en español.
