Antes de reconocer declaraciones, el parser corta el texto en tokens. Esta
sección describe esa etapa léxica de `src/formal.rs`. Responde dos preguntas:
qué tokens existen y si importa cómo se dispone el texto.

## Tokens

<!-- covers: 1 -->

El analizador léxico produce tres clases de token:

- **identificadores**, que incluyen las palabras clave;
- **rutas de import**, entre comillas dobles;
- **símbolos**, de uno o dos caracteres.

| Símbolo | Uso |
|---|---|
| `{ } ( )` | Bloques y listas |
| `, : . ?` | Separador, tipo, campo y tipo opcional |
| `<:` | Subtipo |
| `@` | Tiempo de un evento |
| `=` `=>` | Definición y cuerpo de un efecto |
| `+=` `-=` | Operaciones de un efecto |
| `<=` o `≤` | Implicación |
| `-o` o `⊸` | Cláusula residual |
| `&` `~` | Conjunción y negación evidencial |

: Los símbolos de Formal {#tbl:s3-3-simbolos}

El lexer prueba los símbolos de dos caracteres antes que los de uno. Por eso
`=>` no se lee como `=` seguido de otro signo. Tres caracteres no son tokens por
sí solos:

- `<` sólo existe dentro de `<:` y `<=`;
- `-` sólo existe dentro de `-o` y `-=`;
- `+` sólo existe dentro de `+=`.

Dos conectivos tienen dos grafías. El lexer convierte `≤` y `<=` en el mismo
token, y lo mismo hace con `⊸` y `-o`. La ruta de un import es texto UTF-8
literal, sin secuencias de escape. No puede contener comillas, barras
inversas ni saltos de línea.

## Identificadores

<!-- covers: 2 -->

Un identificador empieza por una letra ASCII o un guion bajo. Sigue con
letras ASCII, dígitos o guiones bajos. Fuera de comentarios y rutas, una letra
como `é` es un error léxico. Las palabras clave son identificadores
corrientes: el lexer no las distingue. Es el parser quien compara su texto
(@sec:s3.5). La comparación es exacta, así que distingue mayúsculas: `Rule`
no es la palabra clave `rule`.

## Comentarios

<!-- covers: 3 -->

Formal admite tres formas de comentario:

- `//` hasta el final de la línea;
- `#` hasta el final de la línea;
- `/* … */`, que puede ocupar varias líneas.

Los bloques no se anidan. El primer `*/` cierra el comentario, y un bloque sin
cerrar es un error. Dentro de un comentario cabe cualquier carácter, también
Unicode. Un comentario separa tokens igual que un espacio. Los tests de
`src/formal/comment_tests.rs` comprueban que un fichero comentado da el mismo
SurfaceAST que su versión sin comentarios.

## Espacios en blanco

<!-- covers: 4 -->

Entre dos tokens puede haber cualquier cantidad de espacios, tabuladores,
saltos de línea y comentarios. El lexer los descarta todos. No hay regla de
disposición, como la de Haskell [@marlow2010haskell], ni sangría con
significado. Las llaves y los paréntesis marcan la estructura. Un espacio sólo
hace falta donde dos identificadores se tocarían, como en `const ana`.

## Comas finales

<!-- covers: 5 -->

Las listas separadas por comas admiten una coma final: argumentos, seeds,
campos de un record, bindings y las demás de @sec:s3.2. Las comas internas son
obligatorias. Así, añadir un elemento al final de una lista no obliga a
tocar la línea anterior.

@Lst:s3-3-amplio y @lst:s3-3-compacto escriben el mismo módulo de dos
maneras. El primero usa los tres comentarios, varias líneas y comas finales.
El segundo cabe en cinco líneas y usa `≤`. Las dos salidas coinciden.

```res {#lst:s3-3-amplio caption="Un módulo en formato amplio" run=run}
// Préstamo: formato amplio, con comentarios.
module Prestamo

entity Person
entity Thing

const ana : Person
const book : Thing
const tau : PropositionTime

seeded verb requests(
    subject : Person,  # quien pide
    object  : Thing,   # lo pedido
)
derived verb lent(subject : Person, object : Thing)

/* Horn: la petición implica el préstamo
   en el instante siguiente. */
rule lending(person, object, t) =
    requests(person, object) @ t
    <= lent(person, object) @ after t

experiment asks {
    seeds {
        requests(ana, book) @ tau,
    }
    query residual lent(ana, book) @ after tau
}
```
::: explanation
El módulo usa las tres formas de comentario. Los argumentos de `requests` y
la lista de seeds terminan en coma. Los espacios alinean los dos puntos de la
firma, sin efecto en el resultado.
:::

```res {#lst:s3-3-compacto caption="El mismo módulo en formato compacto" run=run}
module Prestamo entity Person entity Thing const ana:Person const book:Thing
const tau:PropositionTime seeded verb requests(subject:Person,object:Thing)
derived verb lent(subject:Person,object:Thing) rule lending(person,object,t)=
requests(person,object)@t≤lent(person,object)@after t experiment asks{seeds{
requests(ana,book)@tau}query residual lent(ana,book)@after tau}
```
::: explanation
El texto no tiene comentarios ni comas finales, y casi no tiene espacios.
Los saltos de línea caen en cualquier punto entre tokens. La salida es la
misma que la de @lst:s3-3-amplio.
:::
