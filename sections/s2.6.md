La portabilidad mide en cuántos entornos funciona un programa sin cambios.
Un lenguaje portátil compila y ejecuta igual en distintos sistemas
operativos, máquinas y versiones de sus herramientas. El criterio pregunta
qué necesita el lenguaje del entorno y qué ocurre cuando falta.

La estandarización mide qué define el lenguaje. Un estándar es un documento
externo que fija la sintaxis y el significado. Varias implementaciones
pueden seguirlo, y un programa escrito para el estándar funciona en todas.
Sin estándar, la definición es una implementación concreta y sus tests.

## El criterio en Residuum

<!-- covers: 1 -->

Residuum está escrito en Rust. El paquete Cargo se llama `residuum`, usa la
edición 2024 de Rust y tiene una sola dependencia: chumsky, fijada en la
versión exacta 0.9.3. @Lst:s2-6-cargo cita la cabecera del manifiesto.

```toml {#lst:s2-6-cargo caption="La cabecera del manifiesto Cargo" run=include include=residuum@d4d2282:Cargo.toml#L1-L9}
```
::: explanation
El manifiesto fija la edición, la versión mínima de Rust y la única
dependencia. El signo `=` de chumsky exige exactamente esa versión. La
versión del paquete sigue siendo 0.1.0.
:::

<!-- covers: 2 -->

La versión mínima de Rust es la 1.87. La integración continua la comprueba:
instala Rust 1.87.0 en una máquina Ubuntu de GitHub y ejecuta estos pasos:

- comprueba el formato y clippy, con los avisos como errores;
- compila el binario en modo release;
- compila cada familia de tests sin avisos;
- ejecuta la suite completa con un hilo;
- exige que los informes versionados se reproduzcan byte a byte.

<!-- covers: 3 -->

El entorno de ejecución local es más estrecho que el de compilación. El
launcher y el runner requieren Linux, cgroup v2 y una sesión de systemd del
usuario. Con ellos imponen un límite de memoria, cero swap y timeouts
(@sec:s7.2). Si no pueden imponer los límites, fallan sin compilar ni
ejecutar. La integración continua es la única excepción documentada: llama a
`cargo` directamente, porque sus máquinas son desechables. Los documentos no
informan de ejecuciones en otros sistemas operativos.

<!-- covers: 4 -->

Residuum no tiene un estándar externo. Lo definen la implementación, sus
tests y sus documentos. La referencia del lenguaje es un documento del
repositorio, y un test comprueba que todos sus ejemplos se analizan y
elaboran. El caso jurídico `LegalMonotonicCase` es una referencia congelada,
no una definición universal del lenguaje. La auditoría del núcleo aclara que
su conclusión no certifica la ausencia de errores.

Con una sola implementación, el texto de un documento cede ante el código.
La auditoría encontró que un documento usaba `⊗` como sintaxis del producto.
@Lst:s2-6-tensor muestra lo que hace el lexer.

```res {#lst:s2-6-tensor caption="La notación matemática no es sintaxis Formal" run=expect-error}
module Notacion

entity Person
entity Thing

const ana : Person
const book : Thing
const tau : PropositionTime

seeded verb requests(subject : Person, object : Thing)
seeded verb available(object : Thing)
derived verb lent(subject : Person, object : Thing)

// ⊗ es la notación matemática del producto; Formal escribe &.
rule lending(person, object, t) =
    requests(person, object) @ t ⊗ available(object) @ t <= lent(person, object) @ t

experiment anaBorrows {
    seeds { requests(ana, book) @ tau, available(book) @ tau, }
    query residual lent(ana, book) @ tau
}
```
::: explanation
La regla escribe el producto con `⊗` en lugar de `&`. El lexer rechaza el
carácter y enumera los que esperaba en esa posición. La auditoría corrigió el
documento y dejó el lexer como estaba.
:::

Prolog muestra la alternativa. La norma ISO/IEC 13211-1 fija su núcleo
[@iso1995prolog], y Haskell tiene su informe del lenguaje
[@marlow2010haskell]. @Lst:s2-6-prolog usa sólo construcciones de esa norma.

```prolog {#lst:s2-6-prolog caption="Un programa Prolog que sólo usa la norma ISO" run=none}
:- initialization(main).

requests(ana, book).
available(book).

lent(P, O) :- requests(P, O), available(O).

main :-
    (   lent(ana, book)
    ->  write(lent)
    ;   write(not_lent)
    ),
    nl.
```
::: explanation
La directiva `initialization/1`, la construcción `->` y `;`, y los
predicados `write/1` y `nl/0` pertenecen a la norma. Un sistema que la cumple
debe aceptar el programa. Si un sistema se aparta de la norma, el texto de la
norma decide quién tiene razón.
:::

<!-- covers: 5 -->

Residuum sustituye el estándar por una versión congelada. El tag Git `v1`
identifica, desde el 2026-10-05, la versión semántica del lenguaje y sus
fixtures de referencia. Su documento de alcance enumera lo que entra en v1 y
lo que queda fuera. La versión Cargo sigue en 0.1.0. No se publica un
paquete ni se declara estabilidad general de la API.

El código posterior al tag ya difiere en algunas cotas. La fuente admitida
pasó de 64 KiB a 1 MiB, y el límite de memoria de 1 GiB a 1324 MiB. El
README marca la cota de fuente como configuración de la implementación, no
como restricción semántica. Las extensiones posteriores deben declarar su cambio de alcance.

## Veredicto

Residuum compila con Rust 1.87 en la máquina Ubuntu de la integración
continua. Su ejecución local exige Linux con cgroup v2 y systemd
de usuario. No tiene estándar externo ni una segunda implementación. Lo fijan
una implementación, sus tests y un tag congelado.

Según este criterio, Residuum ofrece un desempeño bajo: una sola implementación en Rust lo define, sin estándar externo, y su ejecución local exige Linux con cgroup v2 y systemd de usuario.
